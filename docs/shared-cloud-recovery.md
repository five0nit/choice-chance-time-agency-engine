# Shared-project quota recovery

This change preserves existing defaults. Opt in all workers that access one Firestore project:

- Provision one owner-only (0700) real absolute directory, including private newly created parent directories. Set `CCT_CLOUD_RECOVERY_DIR` to it in each service environment. Workers derive a SHA-256 project filename and serialize cloud calls through the same OS lock. Never use a symlink or a group/world-writable ancestor.
- Unmapped ownership fails closed, even on read-only mounts. A user namespace maps every unmapped host user to the overflow UID; matching that UID to the namespace root does **not** establish host-root ownership. Read-only service access does not prevent a foreign host owner from swapping ancestors through another mount. There is no namespace-UID exception.
- For a protected systemd service, validate the real source directory outside the user namespace using this same strict validator, then bind that owner-controlled source directly onto a vetted, existing root-level mountpoint inside the service namespace. For example, when `/srv` is otherwise unused by that service: `BindPaths=/path/to/operator-home/.hermes/shared/cct-cloud-recovery:/srv:norbind`, `Environment=CCT_CLOUD_RECOVERY_DIR=/srv`, and `ReadWritePaths=/srv`. Other workers may use the original source path; both views must resolve to the same leaf and project lock/state. The bind pins the leaf for the lifetime of that service mount namespace. Do not use an unchecked host source, a service-needed target, a symlink, or a recursive bind. Retain `ProtectSystem=strict`, `ProtectHome=read-only`, `PrivateTmp`, `NoNewPrivileges` and existing namespace protections. Test with the exact installed interpreter before activation; verify source/bind device and inode identity plus cross-view cooldown suppression. No live mount or unit changes are implied by these examples.
- The bridge and owner connection/work/delivery workers must load this exact package change. Updating only delivery cannot stop older sibling workers consuming quota.
- Keep authority/control reads fresh; no cached permission is introduced. Retry is owned by the outer loop, not SDK retries. Saved cooldowns survive process restart. One failing project probe blocks siblings until its persisted deadline.
- Set `CCT_CLOUD_PROJECTION_HEARTBEAT_SECONDS=600` to coalesce unchanged allowlisted display projections for ten minutes; default remains 120, accepted range 120..1800. Changed content is immediate. The previous verified timestamp remains truthful; cached display data never proves cloud recovery.
- Cache-hit validation, lookup and receipt copying hold the project lock together. A sibling failure persisted first blocks the cached return; an expired failure forces a fresh write. Release this guard before gateway RPCs, which take the same lock themselves. This orders local decisions against persisted failures; it cannot promise cloud health after a returned receipt.
- Lower worker wake frequency through their existing loop/poll configuration where user latency permits. Longer heartbeat alone does not bound repeated authority reads or continuously changing projections. Budget from actual per-tick operations and leave capacity for dashboard traffic.
- A quota circuit does not increase the provider quota. A quota-limited project can remain unavailable until reset. Never raise billing/budgets or bypass fresh authority merely to demonstrate work.

## Verification boundaries

`tests/test_cloud_project_coordination.py` uses separate OS processes with fake SDK transport to prove sharing, sibling suppression, restart preservation and recovery. Its three-day simulated clock proves bounded retries in a synthetic outage, not three days of live reliability.

`python -m cct_agent.reliability_observer --config FILE` reads local ledger/artifact/service/circuit evidence only. Config fields: `home`, `stateDirectory`, `startedAt`, `endsAt`, `units`, optional `circuitFiles`. `endsAt` must be within four days of `startedAt`. Schedule finitely as well. No LLM or Firestore RPCs are used. State binding prevents silent window resets. Persisted notification readbacks are not current external readbacks or Telegram delivery proof. Local duplicate OUTCOME checks do not establish exactly-once remote effects.

A successful trial requires fresh automatic work, independent artifact/acceptance checks, exact cloud notification readback, recorded justified next action, and real elapsed multi-day observation. Service liveness or healthy observer samples alone are insufficient. Preserve outage/restart evidence separately; do not inject false failures into production control state.
