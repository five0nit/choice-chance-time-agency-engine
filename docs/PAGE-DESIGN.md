# CCTAE education page

## Design direction: the Agency Field Guide

**Audience:** agent builders who want useful initiative without noise, invented certainty, or implicit permissions.

**Job:** make the difference between acting, waiting, and asking understandable before installation.

**Concept:** an editorial field guide with a tangible decision docket. Warm paper, ink, ruled evidence rows, restrained vermilion, a serif counterpoint, and large purposeful type—not a SaaS dashboard or a consciousness claim.

**Hero object:** a three-situation docket. Changing the evidence or permission changes the illustrated result. The example is deterministic browser JavaScript, explicitly not the live Python engine.

**Interaction promise:** inspect a concrete decision, follow the governance loop, then run a local cognitive episode. No account, backend, analytics, external fonts, or runtime library.

## Content contract

- `Choice–Chance–Time` describes operational agency, not consciousness or metaphysical free will.
- Observations feed persistent goals/history, allowed alternatives, bounded choice, act/wait/ask, verification, and outcome learning.
- ACT / WAIT / ASK are teaching labels, not an asserted universal three-value kernel API. The kernel's canonical `NO_OP`, initiative `WAIT`, and clarification dialogue are distinct implementation surfaces.
- Choice and exploration happen only among allowed candidates. Seeded chance does not bypass blockers.
- Cooldown, caps, deduplication, and unchanged-state silence limit proactive noise.
- Successful outcomes can change reliability and bounded throughput inside an approved envelope, not create new effect kinds or grant powers.
- The core autonomous filesystem executor is create-only and local. Explicit operator adapters and optional Firebase integrations are a separate opt-in boundary, not evidence that the whole repository is network-free.
- The engine does not sandbox the surrounding agent process or govern unrelated host tools automatically.
- Alpha status is visible. No live counters, fabricated receipts, testimonials, or unmeasured performance claims.

## Responsive and accessibility contract

Design mobile first at 390 CSS pixels, then 1280 desktop. Native buttons and links, visible focus, generous targets, a skip link, semantic sections, and a polite live result region. No scroll-reveal dependency. Reduced motion removes transitions and smooth scrolling. JavaScript controls are revealed only after handlers are installed; an always-readable default ACT example and a `noscript` explanation preserve the lesson without JavaScript.
