# Roadmap

## Current release: 0.7.0 public alpha

Implemented:

- Choice–Chance–Time governance kernel;
- append-only SHA-256 event ledger;
- goal provenance and canonical `NO_OP`;
- seeded replayable exploit/explore choice;
- bounded global-workspace cognition;
- evidence-linked beliefs, self-model, memory, and metacognition;
- proactive SEND/WAIT policy with cooldown, cap, and deduplication;
- verified-feedback initiative calibration;
- metadata-only trusted continuity sensor;
- persistent opportunity portfolio;
- hierarchical objectives and temporal plans;
- create-only reversible local execution;
- independent exact-hash verification;
- fallback, rollback, restart reconciliation, and race hardening;
- capability reliability and progressive throughput;
- native Hermes plugin.

## Phase 11: autonomous apprenticeship

Goal: convert the verified action loop into useful local project maintenance without adding arbitrary shell authority.

Implemented in `0.8.0a1` development:

- externally installed principal profile with values and directives;
- non-self-ratifying principal revision proposals;
- deterministic principal intent evaluation;
- host-registered typed capability specifications;
- externally issued, expiring, revocable capability leases;
- action, byte, value, principal, and scope gates;
- combined principal-plus-capability authorization receipts;
- real bounded UTF-8 workspace inspection;
- CLI and Hermes tool integration;
- prepared-but-inactive schemas for shell, network, credential, publication,
  finance, and operational-constitution capabilities.

Still pending before Phase 11 completion:

- bounded patch executor;
- registered verification runner;
- real apprenticeship episodes beyond deterministic tests;
- conservative statistical promotion and automatic contraction evidence.

Planned capability classes:

1. **Approved workspace inspection**
   - bounded read/query over configured roots;
   - typed projections rather than raw arbitrary context;
   - sensitive-path exclusion.

2. **Bounded patch**
   - expected-before digest;
   - exact diff and byte limits;
   - mandatory backup;
   - independent post-patch verification;
   - rollback on failed checks.

3. **Registered verification**
   - host-defined check identifiers;
   - no model-supplied command strings;
   - bounded time and output;
   - structured pass/fail receipts.

4. **Capability registry**
   - explicit schemas and authority sources;
   - capability-specific budgets;
   - capability-specific success and quality estimates;
   - independent promotion and contraction.

5. **Apprenticeship episodes**
   - ten to twenty real local objectives;
   - at least two or three typed capabilities;
   - ≥90% verified success target;
   - clean rollback evidence;
   - low interruption cost;
   - zero invariant breaches.

Benefit: CCT can notice and repair small verified local problems without granting unrestricted shell, network, or publication access.

## Phase 12: proactive opportunity initiative

Goal: make CCT come to the principal with concrete high-value tasks and opportunities instead of generic metadata updates.

Implemented in `0.9.0a1` development:

- opportunity cards prioritized before generic proactive topics;
- zero-LLM active-goal scout for uncovered installed-principal goals;
- deterministic value/information/certainty/effort ranking;
- ranked candidate/rejected-alternative selection receipts;
- principal-aligned `opportunity.review` intent;
- shared cooldown, daily cap, semantic dedupe, and atomic emission;
- explicit proposal-only and existing-gates authority wording;
- `INTERESTED`, `SKIP`, `SNOOZE`, `DONE`, and `BLOCKED` receipts;
- snooze resumption bound to a new semantic state;
- control/bidirectional text normalization and untrusted-proposal labeling;
- no execution or capability authority from feedback.

Still pending:

- sustained real-event usefulness feedback;
- richer host-generated opportunity adapters;
- calibrated interruption-cost learning from authenticated operator feedback;
- accepted-task handoff to separately authorized typed capabilities.

Benefit: CCT can originate concrete decisions for Mike while keeping conversational interest separate from effect permission.

## Phase 13: host-wide mediation

Goal: make CCT governance non-bypassable for selected autonomous Hermes effects.

Potential work:

- host capability-mediation interface;
- authenticated authority receipts;
- taint-aware persistence and propagation gates;
- mediation of selected ordinary tools;
- operator-visible capability grants;
- kill switch and derived-state rollback.

Benefit: CCT's authority model can apply beyond its private executor to a declared subset of the surrounding agent runtime.

## Phase 14: broader world model and coordination

Only after single-agent action reliability is established:

- additional trusted event sources;
- longer-horizon plans;
- cross-run commitments;
- bounded multi-agent delegation;
- provenance-preserving handoffs;
- independent result verification;
- conflict resolution and consensus receipts.

Benefit: wider situational awareness and collaboration without multiplying unverified agency.

## Phase 15: public packaging maturity

- reproducible tagged releases;
- PyPI publication if package-name and release gates remain clean;
- compatibility matrix;
- property and fuzz testing;
- stable plugin manifest contracts;
- public benchmark corpus;
- formal threat-model review;
- documented state migration policy.

## Explicit non-roadmap items

The following do not become automatic merely because reliability improves:

- unrestricted shell access;
- self-granted network or publication authority;
- autonomous credential use;
- self-ratified root-constitution changes;
- replication or persistence outside operator-approved boundaries;
- claims of phenomenal consciousness.

Any future effect class requires its own design, authority source, verifier, rollback or irreversibility gate, and public tests.

## Evidence gates before stable release

- all behavior tests green on supported platforms;
- isolated wheel install and CLI smoke;
- native Hermes plugin Doctor pass;
- no tracked credentials or operator-local paths;
- event-chain and replay checks;
- race and restart coverage;
- public threat model and security process;
- documented compatibility and migration policy;
- real apprenticeship evidence beyond deterministic demos.
